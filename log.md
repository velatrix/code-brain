## [2026-05-20] project | MediaVault blob storage bucketed by UUID prefix
Flat `blobs/` and `thumbs/` directories were locking Windows File Explorer at scale (~10k+ entries hangs the UI). Switched to `<dir>/<aa>/<uuid>.enc` where `aa` is the first two hex chars of the UUID — 256 buckets, uniform distribution, ~195 files/bucket at 50k-file target. Metadata snapshot stays flat at vault root (non-UUID id). Auto-migration via `blobs::migrate_flat_to_bucketed` runs at unlock; existing flat vaults heal themselves on first open. Tests: 67→82. Cargo check + tests both clean in dev and release. Pushed back on the user's first instinct (mirror app folder tree on disk) because it would leak folder-structure metadata without buying real browseability — see [[projects/mediavault/decisions/0004-bucketed-blob-layout]] for the analysis.

Also separately during this session: gated dev-only `eprintln!` instrumentation in lib.rs / blobs.rs / commands.rs behind a `dev_log!` macro that no-ops in release (via `if false { format_args!(...) }` so the compiler keeps args used and the optimizer DCEs the whole block) — release build is now zero-overhead and zero-warnings. Smart-unit helpers (`fmt_dur_us`, `fmt_bytes`) replaced the integer-truncated `0ms (0MB)` output with readable units.

## [2026-05-20] project | MediaVault recycle bin (ADR-0005)
Soft-delete recycle bin for **files + folders only**. New field `deleted_at: Option<u64>` on `FileEntry` + `Folder`. Old `DeleteFile` / `DeleteFolder` mutations renamed → `PurgeFile` / `PurgeFolder` (same apply semantics, now reachable only from the Trash view). New `TrashFile` / `TrashFolder` / `RestoreFile` / `RestoreFolder` / `EmptyTrash` mutations. `RestoreFile` carries `target_folder_id` so the frontend can resolve the "parent still trashed?" dialog cleanly. Tags + tag groups stay destructive (`DeleteTag` / `DeleteTagGroup` keep their original semantics) — file `tag_ids` bindings are automatically preserved through a file's trash trip because `TrashFile` doesn't touch them. No backward compat (user has no real data yet). Per-item restore. Manual purge only — deferred a retention timer. Trash view is a clone of `GalleryPage`'s shell (NBreadcrumb header + `FileGrid` + selection model), not a bespoke layout. First-pass design over-scoped to tag/group recycling and used tabs in the Trash view — both reverted after the user correctly flagged inconsistency. [[projects/mediavault/decisions/0005-recycle-bin-soft-delete|ADR-0005]] has the full reasoning.

## [2026-05-21] project | MediaVault security audit pass

Four parallel audit agents (crypto / IPC + URI scheme / WAL + storage + concurrency / frontend bugs + state) reviewed the codebase against the design at [[projects/mediavault/design/storage]]. Aggregated 7 HIGH, 11 MEDIUM, 6 LOW/NIT findings; verified the top-severity claims directly before reporting. Then fixed everything except `read_blob_size` header verification (cosmetic — chunk AAD already catches real tampering; ~5–10 ms/range cost not worth it).

Format changes with legacy fallbacks: WAL records now bind `offset` as AAD (pre-existing records replay via empty-AAD fallback); master-key wrap in `vault.json` binds the KDF block (memory/iterations/parallelism/salt) as AAD, with empty-AAD fallback for vaults written before this pass. Behavior changes: `purge_*` refuses unless `deleted_at.is_some()`; `get_blob`/`get_thumbnail` reject non-UUID ids; CSP set (default-src `'self'`, no inline scripts, no external `connect-src`); `validate_entity_name` rejects path separators / traversal / control chars on every create/rename/restore path; `validate_user_path` rejects Windows reserved names and known system directory prefixes for `open_existing_vault` / `prepare_new_vault` / `export_*`; `AtomicU64` generation counter aborts in-flight `stream_blob` exports on `lock()`; `cleanup_tmp_files` only touches our own staging patterns instead of any `*.tmp`; pre-unlock `vault_status` returns only the folder leaf; `Zeroizing` plaintext for WAL + metadata snapshot; 8 GiB import RAM cap; path-leak strip from IPC errors; `parse_range` overflow guard; `shell:default` capability removed (unused). Frontend: `NameConflictDialog` cancel-all now wired to `@close` only (no more programmatic-dismiss conflation); `useGalleryViewStore` localStorage namespaced per vault path + hydrates on unlock / resets on lock; lightbox stale-file watcher in GalleryPage + SearchPage; runImport batches serialized via `importChain` promise to prevent overlapping drop races; em-dashes stripped from 6 user-facing strings + 2 placeholders; TEMP drag-probe `console.log`s removed.

Tests: ~60 new Rust tests across `crypto::tests` (KDF floor, AAD roundtrip, tamper detection), `metadata::tests` (validate_entity_name + sanitize_path_component edge cases), `blobs::tests` (UUID gate path-traversal strings), `wal::tests` (record swap detection, length-prefix tamper Corrupt, legacy fallback), `vault::tests` (KDF floor enforcement, salt-tamper AAD detection, legacy wrap fallback, generation counter properties, purge cascade subtree boundary, restore→purge round trip), `commands::tests` (Windows reserved names, system-dir detection, validate_user_path composite gate). 130 → 190. Briefly stood up vitest + @vue/test-utils + happy-dom for frontend tests, then reverted — most frontend assertions were testing Naive UI event routing rather than MediaVault behavior, and the only logically substantial test target (per-vault storageKey) had low signal/setup cost for a solo-developer desktop app. Full audit posture documented in [[projects/mediavault/design/security]]; [[projects/mediavault/design/storage]] updated with the WAL position binding, KDF AAD wrap, generation counter, and name validation sections.

## [2026-05-20] project | MediaVault sort + view-settings + name-uniqueness
Three features in one session, two of them substantial.

**Sort + view settings** ([[projects/mediavault/design/view-settings]]). `useGalleryViewStore` extended with `sortBy` (`imported|name|mime|extension|size`) + `sortDir` (`asc|desc`), persisted alongside `tileSize` under `localStorage["mv:gallery-view"]` with per-field validation. Pure `sortFiles(files, by, dir)` helper exported, name-asc tiebreaker. `SortControl.vue` renders an NSelect for the key + an arrow-icon button for direction (Up/Down outline, toggle). Mounted in Gallery + Search headers; Trash pinned to `deletedAt desc`. First implementation went with a single 10-option combined select ("Imported (newest first)", "Name (A-Z)", ...) — user disliked "2 of everything" and asked for the split. Also added a gear-icon (`SettingsOutline`) view menu left of SortControl with `Show Flat` — non-persistent boolean ref in GalleryPage that empties `visibleFolders` and merges descendant folders' files into `visibleFiles` via a BFS over `foldersStore.folders`.

**Stored extension on FileEntry**. New `extension: String` field, lowercase no-dot, derived from `name` via `metadata::extract_extension`. Set by `vault.rs::import_file`, recomputed inside `Mutation::RenameFile.apply` (so rename `video.mp4` → `video.mkv` flips the extension atomically in the same WAL record). Old vaults backfilled by `MetadataDoc::fixup_extensions()` called at end of `unlock` after WAL replay. Storage cost is one extra string per file (~3 bytes typical).

**Name-uniqueness** ([[projects/mediavault/decisions/0006-name-uniqueness|ADR-0006]]). Case-insensitive uniqueness for live entities, scoped per natural sibling set (files per folder, folders per parent, tags per group, tag groups global). New `VaultError::NameCollision { kind, name }` → IPC code `NAME_COLLISION`. Four `MetadataDoc::*_collides_*` helpers, called before any persistent write in `import_file`, `rename_file`, `restore_file`, `create_folder`, `rename_folder`, `restore_folder`, `create_tag`, `update_tag`, `create_tag_group`, `rename_tag_group`. Restore checks were added to defend the live-only invariant against the trash-and-reimport sequence.

Frontend: `NameConflictDialog.vue` (Replace / Skip / Keep Both + "Apply to all" + "Keep tags from existing file" — last is only relevant for Replace, default ON when the existing file has tags). GalleryPage `runImport` rewritten to pre-check against folder siblings, queue conflicts, drive the dialog, then process per choice: Replace = `trashFile(existing)` + `importPaths([path])` + optional `setFileTags(new, old.tagIds)`; Keep Both = `findFreeName` (Windows-Explorer ladder) + `importPaths([path], folderId, [override])`; Skip = nothing. Tauri command `import_files` gained `name_overrides: Option<Vec<Option<String>>>` for the Keep-Both override. Inline collision errors in every name-input modal: `RenameFileModal`, `RenameFolderModal`, `CreateFolderModal`, `CreateTagGroupModal`, `RenameTagGroupModal`, `TagEditModal` — all now accept `error: string | null`, render via NFormItem `:validation-status="'error'"` + `:feedback`, disable primary button while set. Parents watch the input and re-validate against the store on every keystroke for live feedback; backend `NAME_COLLISION` sets the error from the message and keeps the modal open. Inline (non-modal) tag-create paths in PropertiesSidebar + TagsPage surface a specific toast on collision.

Tests: 105 → 130 (+25 across +4 extension, +16 collision, +5 from existing work between sessions).

Other small changes this session: sidebar Trash badge moved from absolute-positioned NBadge overlay (cropped by NMenu's content overflow) to NMenu's `extra` slot with `ml-2` for breathing room. Click/wheel/contextmenu listeners on Gallery/Search/Trash moved from the inner NFlex (which sized to content) onto the NScrollbar (full-size container), with `e.stopPropagation()` in FileTile + FolderTile click + contextmenu handlers so tile interactions don't bubble. Right-clicking the background opens a new context menu reusing the existing `addMenuOptions` (Create Folder / Import Files). Researched Tauri 2 native-context-menu disabling — recommended approach is a single `window.addEventListener("contextmenu", e => e.preventDefault())` in `main.ts`; not yet wired.
