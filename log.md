## [2026-05-20] project | MediaVault blob storage bucketed by UUID prefix
Flat `blobs/` and `thumbs/` directories were locking Windows File Explorer at scale (~10k+ entries hangs the UI). Switched to `<dir>/<aa>/<uuid>.enc` where `aa` is the first two hex chars of the UUID — 256 buckets, uniform distribution, ~195 files/bucket at 50k-file target. Metadata snapshot stays flat at vault root (non-UUID id). Auto-migration via `blobs::migrate_flat_to_bucketed` runs at unlock; existing flat vaults heal themselves on first open. Tests: 67→82. Cargo check + tests both clean in dev and release. Pushed back on the user's first instinct (mirror app folder tree on disk) because it would leak folder-structure metadata without buying real browseability — see [[projects/mediavault/decisions/0004-bucketed-blob-layout]] for the analysis.

Also separately during this session: gated dev-only `eprintln!` instrumentation in lib.rs / blobs.rs / commands.rs behind a `dev_log!` macro that no-ops in release (via `if false { format_args!(...) }` so the compiler keeps args used and the optimizer DCEs the whole block) — release build is now zero-overhead and zero-warnings. Smart-unit helpers (`fmt_dur_us`, `fmt_bytes`) replaced the integer-truncated `0ms (0MB)` output with readable units.

## [2026-05-21] project | MediaVault MED batch 2 (M2 + M7)
Same-day continuation after the first MED batch. User invoked the "do what is right not what is cheap" global rule, so picked up the two MEDs I'd flagged as bigger lifts rather than skipping them.

**M2 — gen-counter checks on every multi-chunk decrypt path.** Previously only the streaming exports (`stream_blob` callers) honored lock-time invalidation; the full-file and Range IPC readers ran to completion with their cloned master key even after the user clicked Lock. New `blobs::ChunkCheck` type alias (`&dyn Fn() -> Result<(), VaultError>`) + `noop_check` function for callers under the inner mutex. New `read_blob_with_check` and `read_blob_range_with_check` invoke the callback between every chunk decrypt. `decrypt_chunked_full` gained the same `check` parameter. The bare `read_blob_range` wrapper was deleted because every production caller is the URI handler and must honor lock semantics; forcing the explicit `_with_check` choice at every call site keeps the safety property visible. `VaultState` gained `snapshot_path_key_and_gen` (atomic capture under the inner mutex) and `lock_abort_check` (closure builder); `read_blob`, `read_thumb`, `read_blob_range`, `read_thumb_range` all route through the new variants. `metadata::load` keeps using the no-check `read_blob` since it runs under the unlock-time mutex.

**M7 — `validate_entity_name` + `sanitize_path_component` extensions.** Both functions now cover the four classes the audit flagged: Windows reserved device stems (with or without extensions; case-insensitive), trailing dot or whitespace (Windows FS layer strips these, making `report.docx.` resolve to `report.docx` after export), Unicode bidi controls (the right-to-left override extension-spoof attack), and a 255-byte length cap (every realistic FS we export to caps at this). `WIN_RESERVED_STEMS` + `is_win_reserved_component` moved from `commands.rs` to `metadata.rs` so the entity-name validator and the host-path validator share a single source of truth. `sanitize_path_component` mirrors the new validate rules with substitutions: bidi → `_`, trailing trim, reserved-stem `_` suffix (so `CON.txt` exports as `CON_.txt`), UTF-8-boundary-safe truncation. One existing test (`validate_accepts_filename_with_dots`) was updated because its `"...weird..."` fixture now correctly rejects on the trailing-dot rule.

Tests: 183 → 191 (+2 M2 lock-abort regressions on read_blob_with_check and read_blob_range_with_check; +4 M7 validate regressions for reserved stems / trailing-dot+ws / bidi / length cap; +4 M7 sanitize regressions for bidi substitution / trailing trim / reserved-stem escape / UTF-8-boundary truncation). Release build clean (one pre-existing `ffmpeg.rs` warning unrelated to this work). Updated [[projects/mediavault/design/security]] (§3.3 filename validation, §4 lock-time invalidation coverage, §6 test inventory, §9 file-level reference for vault.rs/blobs.rs/metadata.rs/commands.rs), [[projects/mediavault/design/storage]] (§16 test inventory trajectory), and [[projects/mediavault/_moc]].

**Audit status:** 12 of 19 MEDs landed across both batches. 1 deferred with rationale (M5 — dev HMR CSP origins, low ROI in isolation; queued for the dialog-token refactor). 6 still open: M3 (done as collateral when v2 migration was deleted), M4 (WAL whole-file load — DoS only), M6 (import_files arbitrary host paths — needs dialog-token), M9 (sync Tauri commands on main thread — UI freeze, not security), M10 (unlock mutex through Argon2), M11 (import_file mutex through write+thumbnail). ## [2026-05-21] project | MediaVault MED batch (10 of 19)
Same-day continuation. Walked the 19 MEDs from the second-pass audit; 10 landed in this batch, 1 deferred with rationale, 8 left for a future pass.

**Backend (Rust):** M1 — `blobs::validate_blob_total` caps the header-declared `total` against `MAX_PLAUSIBLE_BLOB_BYTES` (64 GiB) AND against file-size-derived bounds before either reader allocates a Vec; regression test plants `u64::MAX` and confirms both `read_blob` and `read_blob_range` reject as Corrupt. M8 — `salt` decoded from `vault.json` is required to be exactly `SALT_LEN` (16) bytes via `try_into`; `master_key_aad` now takes `&[u8; SALT_LEN]` instead of a slice, comment about "we only get here after length-validated read" is now actually true; regression test plants a 12-byte salt and confirms unlock rejects with Corrupt. M17 — `VaultError::AlreadyExists` dropped its `String` payload; path goes to `dev_log!` only; error.rs mapping unchanged code (`VAULT_EXISTS`), `Display` text generic ("vault already exists in the selected folder"). M18 — `read_import_source` does a `symlink_metadata` no-follow check first to reject symlinks, then a follow-stat with `meta.is_file()` to reject devices/FIFOs/sockets; the stat-zero-bypass-the-cap vector via `/dev/zero`-style symlinks is closed. M19 — `vault::export_file` now captures path+key+gen AND verifies `metadata.files.iter().any(|f| f.id == id)` all under the inner mutex BEFORE `File::create(target)`; closes the "UUID-shaped id with no metadata entry" truncate-any-writable-file gadget that the H1 `is_uuid_id` gate didn't catch on its own. The standalone `snapshot_path_key_and_gen` helper got folded back into `export_file`'s inline mutex scope (was unused after this refactor). 179 → 181 tests.

**Frontend (Vue/TS):** M12 — `useVaultStore.lock` sets `isUnlocked = false` unconditionally after `vaultApi.lock()` succeeds, with `refreshStatus()` wrapped in its own try/catch; missed refresh no longer leaves the UI in a half-locked state. M13 — `GalleryPage.onMounted` registers the drag-drop listener via `getCurrentWebview().onDragDropEvent` AFTER awaiting the store loads; an `isUnmounted` flag, flipped in `onBeforeUnmount`, lets the post-mount async callback call the returned `unlisten` immediately if the component is already torn down, preventing double-registration on re-mount. M14 — `useSearchStore` gains `scrubTagIds(Set<string>)` and `scrubFolderIds(Set<string>)`; `useTagsStore.deleteGroup` and `deleteTag` call the tag-scrub; `useFoldersStore.dropMany` (now the single drop-from-local-state path, called by both `purgeFolder` and `useTrashActions.emptyTrash`) calls the folder-scrub. Without this, active searches silently empty out against deleted ids — especially "all" mode where every comparison against a dead id is false. M15 — `Lightbox`'s window-level Esc handler checks `document.querySelector('.n-modal-container .n-modal')` before emitting `close`, so a layered NameConflictDialog (or any other modal) gets to handle Esc without the lightbox also closing. M16 — `GalleryPage.anyModalOpen()` now includes `conflictDialogShow.value`; Delete / Ctrl+A / F2 no longer leak through to the grid behind an active import-collision dialog.

**Deferred:** M5 (drop dev HMR origins from release CSP) — the attack requires both a local process bound to port 1420 AND a frontend XSS; security.md §5.1 already documents XSS local-exfil as an open question pending the dialog-token refactor; closing M5 in isolation costs a dev-config override + verification cycle for a gain well below the noise. Queued for the dialog-token work.

**Still open:** M2 (read_blob/read_blob_range gen counter), M4 (WAL whole-file load), M6 (import_files arbitrary host paths), M7 (validate_entity_name extension: Windows reserved + bidi controls + length cap), M9 (sync Tauri commands on main thread), M10 (unlock mutex through Argon2), M11 (import_file mutex through write+thumbnail). ## [2026-05-20] project | MediaVault sort + view-settings + name-uniqueness
Three features in one session, two of them substantial.

**Sort + view settings** ([[projects/mediavault/design/view-settings]]). `useGalleryViewStore` extended with `sortBy` (`imported|name|mime|extension|size`) + `sortDir` (`asc|desc`), persisted alongside `tileSize` under `localStorage["mv:gallery-view"]` with per-field validation. Pure `sortFiles(files, by, dir)` helper exported, name-asc tiebreaker. `SortControl.vue` renders an NSelect for the key + an arrow-icon button for direction (Up/Down outline, toggle). Mounted in Gallery + Search headers; Trash pinned to `deletedAt desc`. First implementation went with a single 10-option combined select ("Imported (newest first)", "Name (A-Z)", ...) — user disliked "2 of everything" and asked for the split. Also added a gear-icon (`SettingsOutline`) view menu left of SortControl with `Show Flat` — non-persistent boolean ref in GalleryPage that empties `visibleFolders` and merges descendant folders' files into `visibleFiles` via a BFS over `foldersStore.folders`.

**Stored extension on FileEntry**. New `extension: String` field, lowercase no-dot, derived from `name` via `metadata::extract_extension`. Set by `vault.rs::import_file`, recomputed inside `Mutation::RenameFile.apply` (so rename `video.mp4` → `video.mkv` flips the extension atomically in the same WAL record). Old vaults backfilled by `MetadataDoc::fixup_extensions()` called at end of `unlock` after WAL replay. Storage cost is one extra string per file (~3 bytes typical).

**Name-uniqueness** ([[projects/mediavault/decisions/0006-name-uniqueness|ADR-0006]]). Case-insensitive uniqueness for live entities, scoped per natural sibling set (files per folder, folders per parent, tags per group, tag groups global). New `VaultError::NameCollision { kind, name }` → IPC code `NAME_COLLISION`. Four `MetadataDoc::*_collides_*` helpers, called before any persistent write in `import_file`, `rename_file`, `restore_file`, `create_folder`, `rename_folder`, `restore_folder`, `create_tag`, `update_tag`, `create_tag_group`, `rename_tag_group`. Restore checks were added to defend the live-only invariant against the trash-and-reimport sequence.

Frontend: `NameConflictDialog.vue` (Replace / Skip / Keep Both + "Apply to all" + "Keep tags from existing file" — last is only relevant for Replace, default ON when the existing file has tags). GalleryPage `runImport` rewritten to pre-check against folder siblings, queue conflicts, drive the dialog, then process per choice: Replace = `trashFile(existing)` + `importPaths([path])` + optional `setFileTags(new, old.tagIds)`; Keep Both = `findFreeName` (Windows-Explorer ladder) + `importPaths([path], folderId, [override])`; Skip = nothing. Tauri command `import_files` gained `name_overrides: Option<Vec<Option<String>>>` for the Keep-Both override. Inline collision errors in every name-input modal: `RenameFileModal`, `RenameFolderModal`, `CreateFolderModal`, `CreateTagGroupModal`, `RenameTagGroupModal`, `TagEditModal` — all now accept `error: string | null`, render via NFormItem `:validation-status="'error'"` + `:feedback`, disable primary button while set. Parents watch the input and re-validate against the store on every keystroke for live feedback; backend `NAME_COLLISION` sets the error from the message and keeps the modal open. Inline (non-modal) tag-create paths in PropertiesSidebar + TagsPage surface a specific toast on collision.

Tests: 105 → 130 (+25 across +4 extension, +16 collision, +5 from existing work between sessions).

Other small changes this session: sidebar Trash badge moved from absolute-positioned NBadge overlay (cropped by NMenu's content overflow) to NMenu's `extra` slot with `ml-2` for breathing room.
